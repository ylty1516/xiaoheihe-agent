# 实时发现选题

“账号运营 → 发现选题”按当前平台数据更新，不使用固定游戏名单。
可切换综合热搜、热门游戏、社区热议。显示来源与成功采集时间；采集时间不是新闻发生时间，
平台榜单也不代表全网热度。主榜缺失而使用热议子榜时会明确标注，不能混用排名。

## 更新与变化

- 页面可见、停留在发现选题且开启“自动更新”时，每 60 秒请求新数据。
  隐藏页面、离开发现页或关闭开关后停止定时请求；手动刷新可立即请求上游更新。
- 同一视图的普通请求在 60 秒内共用结果，采集时间不会因此被改成当前时间。
  同时到来的刷新合并；不同榜单、关键词、排序和时间范围的缓存分开，最多保留 20 个视图。
- 新入榜、升降位次与上一次成功采集比较，不是假设平台刚刚出现该话题。
  首次采集不标“全部新上榜”；切换数据源时重新建立比较基准。
- 网络、会话或接口异常时保留该视图最后一次成功结果，标明旧结果和原采集时间，
  恢复后再更新。失败后延迟重试，没有旧结果时直接说明失败，不生成一份假热榜。

## 当前讨论与搜索

点击榜单的“看最新讨论”默认查看近 24 小时、最新发布的帖子。
也可搜索关键词，切换点赞优先、评论优先、平台排序，以及近 7 天、近 30 天或不限时间。
卡片显示帖子发布时间、评论与点赞数据，并可打开原帖。

平台的 `1d` 查询参数实测会返回过期帖子，因此不直接使用它：
取受支持的 `7d` 样本，再按帖子 `create_at` 过滤近 24 小时。近 24 小时的热门排序还补充一份最新样本，
避免只从周榜旧高互动帖中选。没有可靠时间的条目不纳入近 24 小时；已知过期或异常未来时间会被排除。
取回样本数量有限，这不是全站完整统计；没有结果时不悄悄放宽到旧帖。

本地排序尊重用户选择：最新按发布时间，点赞按平台点赞数据，评论按评论数，平台排序保持原顺序。
不会在最后统一改成评论数排序。

## 带入写作

带入的草稿保留来源、采集时间、帖子时间、搜索条件和原帖分区，摘要只作为待核实线索。
优先使用与当前搜索词对应的原帖分区；热门游戏榜可使用其游戏名。
游戏名匹配忽略空白和标点，例如“黑神话悟空”可匹配“黑神话：悟空”。
跨多个游戏且无法确定目标时使用通用 PC 区，留待发布前核对，不继续默认挂《影之刃零》。
此功能不更改已有自动值班的题材范围，也不自动发布。

## CLI 与 agent

```powershell
xhh hot --board all --format json
xhh hot --board games -n 15
xhh hot --board discussions
xhh topic-posts "当前话题" --sort create_date --time-range 1d --format json
xhh topic-posts "当前话题" --sort comment_num --time-range 1d
xhh topic-posts "当前话题" --sort award_num --time-range 7d
```

hot 默认请求上游刷新，`--no-refresh` 可允许上游缓存。
topic-posts 默认近 24 小时、最新排序；需要热度或长期资料时显式切换。
JSON 输出包含来源、采集时间与查询条件，供 agent 按当前结果选题，而不是凭记忆猜热点。
