# 创作领域与写法

创作领域、文章写法、篇幅规格和发布分区分别选择，不把所有内容都写成某款游戏的机制攻略。
默认“按本次要求 / 按内容组织”，用户可以直接说明题材和形式，不必先选标签。

## 题材入口

| 领域 | 可写内容 | 资料重点 |
|---|---|---|
| games | 不同游戏、资讯、攻略、剧情、设计和游戏文化 | 平台、版本、剧透和材料归属 |
| hardware | 硬件、外设、设备使用方法和条件比较 | 规格、测试条件、来源和实测边界 |
| software | 软件、GitHub 项目、开发工具、教程和工作流 | 系统、版本、前提、许可和未验证步骤 |
| ai | AI 工具、应用、提示词、功能整理和工作流 | 模型与版本、演示条件、样例与一般能力的区别 |
| auto | 按用户明确题材处理 | 不把游戏旧文中的数字、例子套到新领域 |

这些是辅助视角，不是题材白名单。其他普通题材也可选 auto 按要求写；现有账号内容禁区仍适用。
扩题材不会给模型增加浏览能力，链接本身不等于资料；需要新事实时附上可核对材料或由 agent 查原始来源。
用户提供的真实体验可以整理，不能把他人经历、文档内容或推断写成作者亲自实测。

## 写法与学习

保留排障、机制、争议、更新、选择指南、考据，增加：

- news：资讯与动态，交代时间、变化、出处及未确认部分。
- tutorial：操作教程，交代前提、操作、结果判据与失败处理。
- review：作品或产品评析，用具体观察说明判断，不冒充实测。
- roundup：盘点与合集，按用途和条件组织，不虚构排行榜或凑数量。
- narrative：叙事与随笔，从材料或真实记录展开，不补虚构的现场和经历。
- essay：观点与短评，区分事实、解释和立场。

候选路线不是必填章节，不强迫不同题材沿同一套“误解—机制—总评—提问”展开。
新写法也可进入选题卡、规划和写法卡；学习接口从同一目录生成可选类型，不再锁死六类。
选段改写仍只处理指定范围，领域标签不会触发整篇重写。

## 面板与发布

AI 助手的“题材与写法”按需展开；主编辑区仍只有标题和正文。
领域、写法和规格会随草稿保存，并在复制、回收恢复后保留。
新稿先使用通用分区建议；游戏领域保留 PC 游戏基础区，非游戏领域不自动附加该区。
已有旧稿、旧脚本保留原路由，显式选择创作领域后使用新设置。

发布分区可搜索平台真实候选再选择，不把模糊搜索的多个结果中的第一个当作用户选择。
分区查询失败时尚未提交正文，可以继续本地编辑；提交后网络中断则先核对远端结果，避免重复发布。
分区建议不是预先确认可发布的保证，发前仍以平台解析结果为准。

```powershell
xhh draft --md 工具教程.md --title "工具教程" --subject software --profile flexible
xhh publish --md AI清单.md --title "用途与边界" --subject ai --topic "实际分区名" --profile short --yes
```

CLI 未指定 subject 时读取草稿设置；无设置的旧稿沿用旧行为。新增范围不改变已有值班的游戏、数量、时间窗口或发送授权。

领域与写法目录在 `content/writing.py`，面板选项和 CLI 领域选项从这里读取。
发布成功后记录领域、写法与正文；生成跨领域稿件时只使用同领域历史作内容参考，查重仍对照全部已发正文。
