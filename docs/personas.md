# 统一人设卡

所有入口共用 `content/persona.py`：WebUI 写作、自动成稿、CLI 评论、WebUI 评论与外部 agent 使用同一份卡、场景设置和表达规范。人设是账号的表达配置，不改变 agent 自身全局身份、事实要求或发帖/评论授权。

## 日常使用

WebUI 顶部显示当前人设名称。打开后主要编辑「人设描述」「例文与改稿示例」两个区域；场景补充、名称与历史版本折叠收纳。示例可以直接粘贴喜欢的片段，也可以按以下方式填写，多组用单独一行 `---` 分隔：

```text
素材/要求：假设本次更新修复启动崩溃、新增手柄改键。写两句资讯。
参考成稿：这次更新修了启动崩溃，也加了手柄改键。遇到这两类问题的玩家可以留意。
修改前：本次更新体现了团队对体验的高度重视，为游戏发展注入新的活力。
```

示例只教表达，不作为本次事实或个人经历。不同文章保留句式、结构和篇幅变化。词语和正常连接词不设统一黑名单，不用“AI检测分数”判断质量。

「保存并使用」创建新修订并将其用于后续生成。版本恢复同样创建新修订，不删除历史。并发编辑采用修订号检查，冲突时不覆盖另一个窗口。切换卡片会暂存本窗口的未保存编辑；刷新页面前应保存需要保留的修改。

## 现有人设迁移

v0.6.0 内置「白川澪 · 游戏社资料委员」作为未选择人设时的默认卡，安装包自带完整描述、8组例文和4种场景。已明确选择的人设在升级时保留，想切换可在 WebUI 选择后保存使用，或执行 `xhh persona activate --id shirakawa-mio`。

原有 `voice/profile.md` 作为「现有人设」保留；缺少此文件时该卡采用中性表达。读取不会创建数据库或改原文件。首次编辑保存内置卡或原人设时，将原内容归档为修订0，再保存修订1。私人身份不改写、不提交仓库；卡片和版本存于项目 `.data/personas.sqlite`。

现有文件可能混有评论和文章约定。文章的场景默认要求明确区分评论短句、少转折等规则，避免将它们统一套到长文；用户可在场景补充中调整。旧文件保留用于追溯，保存卡片后生效内容以卡片版本为准。

## AstrBot 导入导出

参考 [AstrBot 人格管理](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/persona_mgr.py) 与 [人格注入流程](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/astr_main_agent.py)。导入支持平铺 JSON：

```json
{
  "persona_id": "author",
  "system_prompt": "你的性格、语气和表达偏好",
  "begin_dialogs": ["素材或用户要求", "认可的成稿"]
}
```

`begin_dialogs` 为偶数条字符串，user/assistant 交替，最多8组。缺少示例可用空列表。重名导入会创建新编号，不覆盖已有卡，也不自动切换当前人设。

导入仅提取表达字段。工具、技能、权限或模型密钥字段不执行、不存入卡片，界面会列出忽略的字段名。导出 AstrBot 格式保留 `persona_id/system_prompt/begin_dialogs`；本项目的场景补充和修改前示例需要选择「完整人设卡」格式保留。导出内容来自已保存版本，未保存的修改应先保存；文件中包含私人设定时按自己的保存位置管理。

## 外部 agent 与任务一致性

```sh
xhh persona prompt --scene article
xhh persona prompt --scene comment
xhh persona list
xhh persona import --file persona.json
xhh persona activate --id author
xhh persona export --id author --format astrbot
xhh persona rollback --id author --revision 1 --expected-revision 3
```

可用 `--root` 指定项目。`prompt` 输出当前修订、摘要校验值、表达规范版本和合成后的指令；外部 agent 动笔前读取对应场景，不再各自复制语气规则。`show --revision` 可读指定历史版本。卡片编号、修订和摘要随生成结果返回；采用正文后写入稿件元数据。

自动任务在创建时保存人设快照。后续切换或编辑当前人设，不影响正在写作、等待图片或恢复中的原任务。规划、事实核对和权限检查不注入角色扮演，避免人格要求影响证据判断。历史任务首次继续时固定当时的当前卡。

手机原生面板显示主机当前人设名称和修订，可点「切换人设」进入列表直接选择；切换只影响新任务，面板读取不自动切换。实际写作由同主机的后端加载。编辑卡片在 WebUI 完成，不额外要求在手机、电脑或每个 agent 中重复填写。

## 试写与编辑检查

「试写两版」可选择长文、短帖、教程或评论场景，用相同素材分别调用已保存版本和当前未保存版本，每次最多两次文本生成，只展示结果，不采用正文、不切换人设、不公开发布。

共用的表达检查返回具体片段及修改建议，作为提示，不会因出现“但是”“因此”就拦稿。自动任务遇到多个具体表达问题时最多做一轮编辑，模型调用计入原有预算，编辑后仍需核对事实与来源。手工稿和外部 agent 稿经现有发布检查时同样得到这些提示；不保证外部 agent 绕开项目发布入口的行为。
