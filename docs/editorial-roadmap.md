# 个人编辑部实施方案

目标：从一次性生成帖子发展到持续取材、保存个人观察、判断内容增量、制作、复盘与维护。已有发布授权与频率规则保持独立，任何新入口不默认公开发帖。

| 顺序 | 交付 | 验收 |
|---|---|---|
| 1 | 事件档案与多源取材 | Steam 游戏新闻、GitHub 发布记录、用户资料可归档；同一内容转载去重，保留时间、出处及来源属性 |
| 2 | 内容问题与观点记忆 | 保存读者问题、结论、信息增量和来源；识别内容重叠，保留已有正文查重 |
| 3 | 手机素材收集 | 原生入口保存输入框文字；素材可直接用于自动成稿，个人记录不自动升级为实测 |
| 4 | 栏目与专题 | 同一事件中的资料、稿件、问题和反馈可持续积累，按读者需求组织选题 |
| 5 | 验证记录 | 保存环境、方法、结果和附件；区分用户提供的记录与工具实际执行的验证 |
| 6 | 配图制作 | 保存每图用途、插入位置和来源/生成属性，沿用插件生图回填，不冒充证据 |
| 7 | 发布后反馈与维护 | 获取平台实际返回的互动数据；未知指标留空，记录读者问题和更新线索 |
| 8 | 手机处理例外与运行控制 | 收集素材、看结果；明确暂停/取消，限制任务时长和模型调用次数，不自动恢复用户主动暂停的任务 |

开发采用逐阶段提交，先打通资料到文章的链路，再扩展长期运行。评测除了现有流程测试，还需用同一题材连续多稿验证问题、结论和证据是否重复。语义模型给出的是编辑建议，不能证明事实真实。

外部接口只读取固定的 Steam/GitHub 公共 API；不通过任意 URL 抓取本机文件或内网。不自动安装或执行外部项目。实验材料可以由 agent 在其已有授权内实际运行后提交；没有执行回执的材料标为提供的记录。

预算第一版控制可验证的模型调用次数和墙钟时间，不将估算价格显示成真实账单。Android 原生组件用上游 SDK 验证，真机体验须另做实机验收。

## 第一版实现进度

八项均已接入基础链路：`content/desk.py` 提供专题归档与内容记忆；`webui/research.py` 提供固定公共 API 采集；`webui/autopilot.py` 使用素材、比较信息增量、归档稿件和图片用途、采集反馈、限制运行预算；`webui/experiments.py` 执行受限验证配方；WebUI 与手机原生入口负责收集素材和控制任务。

第一版的明确边界：事件按专题名归档，尚不自动推断跨语言实体关系；语义重复判断是模型建议，不能证明新颖性或事实正确。原始个人语音/截图仍通过宿主已有能力转写或上传，本轮原生入口先支持文字随记。栏目由专题组织，尚不自动排完整周计划。数据反馈只记录实际返回的点赞、评论数，阅读量未知时留空；不做小样本的因果归因。新资料提示复核旧稿，不自动改写已公开帖子。生图仍依赖宿主能力。隔离运行第三方项目、自动截图、自动评论归纳与 Android 真机验收留作下一批扩展，不声称已经完成。

WebUI 顶部「专题素材」收集随记、读者问题和验证记录，也可输入 `steam:AppID` 或 `github:owner/repo` 读取资料。点击素材的「据此成稿」创建新任务。服务运行期间每两小时检查已登记公共来源（每轮最多四组），每三十分钟采集最近两篇已确认发布任务的反馈。待处理的旧稿提示在素材台显示。

`POST /api/desk` 的 `action=experiment` 支持 `recipe=runtime` 和 `recipe=project-tests`；后者只测试当前项目，显式调用才执行，不接受任意命令。`POST /api/autopilot` 新任务可给 `max_model_calls`（1–30，默认10）和 `max_seconds`（1–1800，默认300）；同端点 `pause/cancel/resume` 控制已有任务。主动暂停不会被后台自动恢复，公开提交阶段不能暂停后重发。
