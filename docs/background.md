# 后台常驻与每日发帖

Windows 可用 `powershell -NoProfile -File scripts/background.ps1 -Action Install` 安装并立即启动常驻后端。登录当前Windows用户后自动运行，窗口关闭不停止；只监听127.0.0.1:8765，适用于同主机DSH Go。服务退出后30秒重试，进程异常退出由任务计划程序重启。已存在后端时监测并复用，端口被其他程序占用时等待，不悄悄切换端口。无需管理员或保存Windows密码。

查看状态、启动、停止、卸载分别使用同一脚本的 `-Action Status`、`Start`、`Stop`、`Remove`。任务名称为`xiaoheihe-backend`；日志在`.data/logs/background.log`，轮转保留。停止任务仅停止它托管的服务，手动启动的其他服务需从原入口停止。不自动改系统睡眠设置。

## 每日GitHub创作

常驻服务与定时创作是两件事：启动后端不会自行新建或发布文章。用户授权后，通过Codex/ChatGPT桌面应用的定时任务在当前聊天中每日接续。当前用户约定为北京时间每天10:00，自动写并发布一篇GitHub帖子，两个分区GitHub与AI。不得因为安装启动器立即试发真实帖子。

任务读取原始仓库/官网资料，检查最近已发正文，使用已选人设与本任务冻结的配图设定；保持正文语气，添加清楚的小标题、适量emoji和真实官网截图。按既有长文偏好准备相关图片，生成图与实拍/官网截图明确区分。等待配图时由宿主agent调用已授权的内置生图工具并回填；后端本身没有聊天生图能力。

每天先核对`.data/github-daily/YYYY-MM-DD.json`、自动任务与发布记录；已有当天成功发布则不再发布。已有任务先接续，进入提交或结果不明时先核对账号实际状态，不另建任务或重发。记录创建的任务ID、正文文件、已提交与已发布状态及link_id。重启不能清空记录。一个任务跨日期完成时同时登记实际发布日，避免次日又发。

每日一次是目标与上限，并非无条件保证：登录失效、无合格资料、检查未通过、宿主生图不可用或发布结果不明时保留现有稿件并报告阻碍，不降级检查、不编事实、不自动多发或事后补齐多天额度。只授权发帖，不增加回复/私信权限。

## 运行条件

本机还配置了Windows启动文件夹中的`Xiaoheihe-Agent.lnk`，登录后打开已安装的Codex/ChatGPT桌面应用。此快捷方式属于本机配置，不随仓库安装器传播；不再需要时可从Windows启动文件夹删除。不会替用户登录应用、处理验证码或绕过账号验证。

本机定时任务需要电脑开机、网络可用、当前用户会话及桌面应用保持运行（可以最小化），不能只留下Python服务后退出Codex。后台进程不会阻止睡眠，睡眠期间无法工作；关机期间无法执行。Windows登录自启后端不等于系统登录前服务，也不保证错过时段补跑。

[官方桌面定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)明确本地项目需要电脑开机且应用运行。DSH Go连接电脑时也依赖该电脑在线。现有评论扫描和学习任务不由此安装器更改。

每日签到与分享任务的真实进度可开启[每日任务检查](daily-tasks.md)；当前仅支持监测，App签到及真实对外分享尚未接通，不把后台在线当作任务完成。
