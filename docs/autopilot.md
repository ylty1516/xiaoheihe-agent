# 自动成稿与插件配图

专题追踪、素材收集、内容增量判断、验证记录、发布反馈和主动暂停见 [个人编辑部实施方案](editorial-roadmap.md)。

WebUI 点「自动完成」，可只填一句要求，也可留空从GitHub相关讨论选题。点一次后在后台依次读取资料、规划角度、写正文、保存新稿、核对事实和检查重复；不再要求先建稿、手填选题卡、选提纲、采用正文和手动保存。

「调整本次任务」内可选择短帖/按材料决定/长文、是否配图、是否使用当前稿的材料，以及完成后自动公开发布本篇。默认只成稿；勾选自动发布并启动即授权这一次任务，无须在每个阶段重复确认。题材与写法沿用 AI 助手中的选择。

这是一篇一篇执行的任务，不会新增定时发帖或改变已有《影之刃零》值班的题材与时间。

## 后台与恢复

- 关闭弹窗或浏览器不会停止任务，WebUI 服务需保持运行。
- 来源、规划、正文和配图进度持久保存在 `.data/autopilot/`。服务重启后继续尚未完成的提交前工作，不重新生成已有正文。
- 没有材料时读取社区近期正文，默认近24小时；指定话题无结果可补查近7天，并保存来源发布时间。榜单标题不能代替正文，采集时间不能当事件时间。
- 社区资料仅代表对应作者的说法，不自动升级为官方事实或亲身实测。规划中的引文必须能在已读取材料中逐字定位；事实核对发现问题时自动修正一轮，仍有问题保留待处理稿。
- 用户手动改过稿后，不覆盖修改或继续自动发布。
- 仅发布时段或间隔未到且其余检查通过时，服务每30秒检查一次，允许后继续。重复、来源或其他检查问题不会被自动勾选忽略。
- 已进入提交但没有可靠结果的任务会停在“结果待核对”，重启、继续和重复点击都不会再次提交。不同服务/CLI 自动任务通过本地锁互斥。

## 插件自动配图

Python WebUI 无法直接调用聊天里的内置生图工具。需要生图时，它会保存正文及每张图的用途、提示词、插入位置，任务显示等待配图。v0.6.1 起，每张提示词已合并任务冻结的人设外观与视觉方向，宿主直接采用完整提示词，无需再次手填角色；不同图按内容改变构图。由有内置生图能力的 agent 执行接续，无需用户下载、选文件、上传和粘贴 Markdown：

```powershell
xhh autopilot list
xhh autopilot images --id <任务ID>
# agent 根据每条请求调用当前可用的内置生图工具，保存输出后回填：
xhh autopilot attach --id <任务ID> --image-id <配图ID> --file "F:\Codex_Save_Library\01_Generated_Images\example.png"
```

最后一张图回填后自动继续插入图片、检查及本任务已授权的发布。注明 AI 生成示意，不当成游戏截图、官方画面或测评证据。不为了满足数量虚构证据图片。没有 agent 接续的独立 WebUI 会保留等待状态，不能声称生图正在后台自动发生。

用户允许时可调用其指定的内置图像模型；实际模型由宿主提供。当前工具没有模型选择参数时，不伪造 `image2.5` 参数，也不擅自改用付费 API、索取密钥。

## 命令行入口

```powershell
# 不给要求时，从GitHub相关讨论选题；按需篇幅，默认只保存本地稿
xhh autopilot run
# 已有资料可不连接账号成稿（仍需文本模型）
xhh autopilot run --instruction "把这些材料写成软件教程" --subject software --genre tutorial --material-file material.txt --images none
# 已授权本篇自动公开发布时才使用这两个参数
xhh autopilot run --query "明确话题" --publish --yes
xhh autopilot status --id <任务ID>
xhh autopilot resume --id <任务ID>
```

命令行单次执行结束后不会驻留；等待发布时段的自动继续由运行中的 WebUI 服务负责。失败保留已有结果，`resume` 不重写已完成阶段，发布结果不明时拒绝再次提交。模型设置沿用该项目的本机配置，凭据不进入任务 JSON 或仓库。


v0.7.0 新任务默认分区为GitHub和AI；可在自动成稿窗口调整，或重复传入 `--topic`。任务冻结其选择，具体规则见 [指定发布分区](publishing-topics.md)。
