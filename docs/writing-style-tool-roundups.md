# 工具合集与配图

参考来源：[小苏叶的 GitHub 项目合集](https://xiaoheihe.cn/app/bbs/link/195536438)，阅读日期2026-11-02。本页记录可迁移的编辑方法，不复刻原文、人物或未经核对的推荐结论。

## 内容节奏

短引子交代这次帮谁解决什么问题。条目用「编号＋项目名＋一句具体用途」作为扫描入口，紧接紧凑资料栏，再解释功能、适合的任务、前提和必要局限。可用少量列表帮助比较，不把每条都硬塞同样长度与栏目。

有可靠的统计快照才做周榜并注明起止日期；只有当前仓库数据就做用途精选。原帖部分插画数字与正文存在数量级差异，不能复制到新稿。星数是受关注程度，不是性能、可靠性或推荐质量的证据。原帖的第一人称使用记录也不能移用。

项目数量由本期材料决定；角色旁注按需要出现。收尾可以给出适用人群或选择建议，不固定问句、求赞或升华。游戏仍是主要方向，硬件、软件和AI工具可独立成篇。当前不改变既有自动发帖任务的题材与排期。

## 自己的视觉身份

白川澪采用原创白发、蓝色发夹、校园资料委员形象；人物外观和画面方向存入统一人设卡。角色有认真核资料、看到实用小设计会高兴、会轻轻吐槽的特点，不借用参考帖的动物耳朵、面具、服装或作者标识。

参考的是「信息卡＋角色＋解释图形」的导览方式。每张插画根据具体项目改变动作、构图与图形；封面重主题，段落图解释用途，流程图优先可读性且可以不放人物。色板和识别特征一致，不等于每张贴同一张立绘。

## 插画与事实分工

生成插画可以承担主题表达、项目导览和概念解释；原始文档、真实界面截图和可追溯记录承担事实说明。生成图不伪装运行截图或实测结果。没有核对的数字、许可证、日期与代码就不写进图；复杂表格、密集代码和小字说明优先保留为正文。

学习卡保存在 `notes/study/cards/195536438.json`，写作时按选题适配，不全局锁死为同一格式。当前人设的文章场景也包含可选合集节奏。


## 本次示范修订后的排版约定

项目合集的主章节优先使用二级标题，必要时加粗，章节之间用分隔线或明确留白；三级标题用于章节内部的小项，避免项目主标题与正文混在一起。emoji可以在项目标题、提示便签等位置少量点缀，数量按内容需要，不要求每段出现。

配图兼顾角色导览与原始项目资料。有可读取、适合展示的官网或官方文档时，加入真实页面截图，图下注明来源和截图日期；保留页面原有标识，不把截图说成本篇安装实测。不用AI图填充所谓“官网截图”。正文缺少可用截图时说明实际情况，不能凭空制造。
