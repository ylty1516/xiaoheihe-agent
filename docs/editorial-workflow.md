# 写作流程与唯一规则来源

本文取代旧的四段式、强制相邻话题、固定问句收尾和按排版撞车退稿规则。
`voice/profile.md` 只定义账号语气；不在这里改动私人身份设定。
其中关于短句、少转折和不列点的偏好用于评论回复；文章的结构、连接词和篇幅以本文为准。

## 按本次任务使用

- 原有长文偏好是默认规格，不是所有用途的硬门槛。用户给定主题、稿件或修改范围时直接处理，
  不必先逛热搜、登录、填卡或比较三份提纲。合集、清单、问答也可按要求组织。
- 内容规格由 `content/stats.py` 统一实现，CLI、WebUI 与检查脚本共用：

| 规格 | 适用场景 | 篇幅与配图 |
|---|---|---|
| article（长文，兼容默认） | 原有长文偏好、现有值班 | 至少 1000 字，推荐 1500–2500，至少 3 张相关图 |
| short（短帖） | 简短观点、说明、短攻略 | 不强制配图，超过 800 字仅建议精简 |
| flexible（按需） | 自定篇幅、无图稿、特殊形式 | 不预设目标字数和图片数量 |

空内容不能公开。short/flexible 的表情与口头禅密度只提醒；规格不改变账号授权、排期、
完全重复正文拦截或平台要求。未完成稿可先保存，不必达到发布规格。

- 本次要求优先于默认篇幅、语气和方案数量；没有要求时沿用草稿规格，否则延续长文偏好。
- 保留现有账号授权、发布确认、排期、分区与内容禁区。
- 不虚构游玩经历、测试结果、数字、引文；事实注明来源、时间或版本。
- 原有长文值班写稿先填选题卡，再选择论证方式。WebUI 手写稿只需标题与正文，
  不要求人工逐项填卡；已有选题卡仍保留参与比较。没有足够证据时保存草稿，不凑字发布。
- 普通单篇建议聚焦一个问题；明确要求合集、多项对比或问答时按任务组织，不强拆单题。
- 自然使用“但是、不过、其实”等连接词。“打不过”不会再被当成禁词。
- 开头、收尾、小标题和段长由文章目的决定；不强制提问、表态或故意打乱句长。

下面的选题卡、多案比较和学习流程按需使用，主要面向连续创作与长文值班。
仅润色一句、依据现有稿件改写、查指定帖子时不要求走完。排版相似只作提醒。
文本重复检查是保守的启发式，不是语义新颖性证明，也不核实来源真假。

## 1. 先看旧文与社区，再填选题卡

```powershell
py scripts/editorial.py audit
```

它读取最近 5 篇已发布正文，带原文摘录统计社区声音开场、翻帖叙事、问句/二选一收尾、
后半篇评分罗列等可观察习惯。历史为空时先补录已核实的公开正文，不能拿草稿代替。
这只覆盖部分写法，不是语义分析或质量分数。相同语气可以保留，阅读路径要由本篇任务决定。

自由找选题时可运行 `xhh hot -n 5` 与 `xhh topic-posts 游戏名 -n 10`，数量按需要调整；
已给定选题或资料时不强制重复找热点。
实时讨论默认近 24 小时、最新排序；需要当前高互动样本时可加 `--sort comment_num`，
需要回顾资料时显式改为 `--time-range 7d` 或更长。不要把旧高互动帖或采集时间当成新闻刚发生。
面板的自动更新、三种榜单和时间过滤见 [发现选题](discovery.md)。
运行：

```powershell
py scripts/editorial.py init .data/post-new.md
```

编辑生成的 `.data/post-new.brief.json`：

```json
{
  "reader": "这篇帮助谁",
  "question": "本篇只回答哪一个问题",
  "conclusion": "主要结论，注明适用条件",
  "new_information": "相比历史文章新增的事实或论证",
  "exclude": ["已经写过、这篇不再展开的内容"],
  "structure": "mechanism",
  "facts": [{"claim": "具体事实，保留版本与条件", "source": "https://原始来源地址"}]
}
```

链接格式校验不代表内容已查证；agent 必须实际打开核对。可先保存不完整选题卡，
补全后才能通过写作检查。旧稿没有选题卡时提醒补录，兼容原有稿件。

## 2. 比较三种提纲

```powershell
py scripts/editorial.py plan .data/post-new.md
py scripts/editorial.py library --query mechanism
```

六种类型描述用途，不代表六套必填的四段模板：

| ID | 用途 | 必需的素材 |
|---|---|---|
| troubleshooting | 帮读者找到下一步 | 可核对的条件和操作，不虚构实测 |
| mechanism | 解释某条规则如何起作用 | 规则依据和具体案例 |
| debate | 弄清分歧的条件与依据 | 双方原始主张与证据 |
| update | 判断一项变化影响了什么 | 版本记录与前后资料 |
| guide | 帮读者按条件做选择 | 可比条件，遵守账号内容禁区 |
| investigation | 确认一条说法能成立到哪里 | 可追溯来源与缺口 |

每份计划还给出读者任务、切入、推理路线、所需证据、收尾和配图用途。
可沿一个场景还原状态变化、按条件给下一步、核对流传说法、同条件比较、追踪变化，
也可先给窄结论再解释边界。命令优先所选类型，在兼容路线中参考最近使用情况；
并列提供相关类型作比较，不强迫轮换，不随机切换话题。

这些是推理工具，不要求照抄章节或平均分配段落。素材不足时补证据、收窄结论或存草稿，
不能为了结构多样而编出实测、双方争论或前后对比。选定路线可记到选题卡可选字段 `route`，
使用计划返回的 ID；未填写时照常写作，不增加 WebUI 必填框。

比较多案时须能说明不同的证据用途与读者收益，不能只是同一篇文章换三个标题。
数量以用户要求和素材为准，也可以不出提纲直接写正文。
保留主题和问题，不靠插入评分、在线人数或相邻机制撑篇幅。

### 证据与配图怎样进入文章

- 区分原始规则、他人体验、作者推断和待验证事项；链接存在不等于已经读过。
- 评论热度用于发现问题，不能证明机制、所有玩家体验或错误的根因。
- 总死亡次数/总时长不能推导前后期死亡分布；总人数不能推出玩家构成。
- 总评分不能代替对本篇具体命题的论证。删去数据后推理不受影响，就应考虑删去它。
- 图片应解释规则、条件、操作、对照或边界，逐张对应证据；通用海报不能冒充实测结果。
- 不默认使用“社区一句话→罗列机制和评分人数→总评→提问”的串联方式。
  不每篇都写“我翻了很多帖子、盯着看了半天”；确有查证过程且有信息价值时才写。

## 3. 写稿与修改

面板默认只显示标题与正文，自动保存。文件名自动生成，在草稿箱中以文章标题识别。
支持 Markdown 导入导出、复制、回收恢复、配图上传与排版预览。
AI 助手按需接入用户配置的兼容模型：资料和要求放进一个输入区，可生成提纲、
正文或改写选段；结果先审阅再采用。模型不会自动访问材料中的链接。
AI 和发布弹窗都可选择“长文 / 短帖 / 按需”，同一草稿的规格会自动保存，两处同步。
局部改写只处理选段，不附加长文结构要求；提纲支持一份或多份分别采用。
写作上下文包含最近已发布正文的开头、结尾和习惯摘录，避免只凭标题比较。
写法卡按材料相关程度检索，并保留证据用途、适用条件和不宜模仿之处；不再固定取前四张。
生成正文后会再检查可观察习惯和图片资源复用，提醒可在 AI 结果中查看。
“草稿箱 → 已发布记录”可展开最近写法的原文对照，不增加编辑区输入项。
正文改变后旧选段失效；多窗口保存通过版本校验避免覆盖其他人的修改。
没有选题卡时仍比较正文近似，明确提示核心问题与证据无法自动比较，不虚构一份卡来通过检查。

## 4. 内容与形式分开检查

```powershell
py scripts/check_post.py .data/post-new.md
py scripts/check_post.py .data/post-short.md --profile short
py scripts/check_post.py .data/post-custom.md --profile flexible
py scripts/editorial.py review .data/post-new.md --require-brief
py scripts/style_profile.py compare .data/post-new.md
```

- 内容检查对照最近 20 篇**已发布快照**：近似段落、复用事实、相近核心问题与结论。
- 完全相同的长正文拦截；近似内容提醒人工检查实质增量，避免误伤必要引用。
- 写法习惯与文本重复分别返回；少于 2 篇或未达到近期多数的习惯不提醒。
  一句问话、同一个游戏或同类标题本身不会拦截发布。
- 相同图片资源跨黑盒域名/缩略图参数仍能提醒复用；这不代表能识别图片视觉内容或版权。
- 选题卡字段不全或格式错误必须补齐。检查不到的同义改写仍需编辑判断。
- 排版对照最近 3 篇已发快照，编号标题和问句标题分开识别，忽略独立的“喵~”署名。
  相似只提醒，不通过换图片位置或凑篇幅证明“新颖”。
- 历史损坏会报错，不静默当成“没有重复”。历史为空会明确说明缺少比较依据。

CLI 和面板都执行内容检查。`--allow-short` 不会绕过选题卡或完全重复正文检查。
面板原有提醒确认和发布确认保留。
`xhh draft/publish --profile article|short|flexible` 可覆盖草稿保存的规格，省略则读取同名
`.meta.json`，没有设置时沿用 article。该选择与平台 article/dynamic 类型无关，CLI 仍用富文本 article 提交。

## 5. 发布后记录，旧文补录

成功公开并拿到 link_id 后，CLI 和面板自动保存正文与选题卡到
`.data/editorial-history.json`；存草稿和失败发布不会写入。编辑同一 link_id 时更新原记录。
远端已成功而本地登记失败时，会明确提示“已公开，勿重发”，再补录即可。

原排期账本没有旧文正文，不能凭空迁移。核对已公开文章后手动补录：

```powershell
py scripts/editorial.py import 已发布原稿.md --link-id 真实ID --title "真实标题" --published-at 真实Unix秒
```

此命令只登记内容记忆，不发布，也不改变排期账本。不要补录未发布草稿。
旧文应传实际发布时间，避免按补录时间排序；编辑同一 link_id 默认保留原发布时间。
旧文只有公开正文时可不伪造选题卡，写法比较仍能工作。

## 6. 让学习留下结果

`xhh study` 按互动热度并参考标题关键词分散样本，仍需人工判断质量和类型。
除正文笔记外会产生 `.writing.json` 待分析卡，初始状态为 pending：

- `article_type`：上表中的类型；`reader_question`：读者问题。
- `argument_order`：论证顺序列表；`evidence_usage`：如何使用证据。
- `applicable_when`：适用条件；`avoid`：不值得学的地方。
- `link_id` 与 `source_url`：保留出处。

读完全文填写后：

```powershell
py scripts/editorial.py learn notes/study/日期-ID.writing.json
py scripts/editorial.py library --query 排障
```

完整卡进入 `notes/study/cards/`，面板 AI 写作会参考已学卡片。也可在“账号运营 → 发布与学习”
阅读原文并点击 AI 拆解，校验完整后保存卡片。原文只抓下来不算学会，
不要把他人的体验写成自己的经历。

## 验收

用同一款游戏连续规划五篇，分别记录核心问题、独有证据和结论。
检查新增信息是否成立、重复提示是否准确、需要删改多少内容。
自动化测试覆盖规则边界、发布成败记忆、路径限制与局部编辑接口；实际文风仍需阅读评价。
