# 发帖内容策略

账号发两类内容，别跑偏喵。

---

## 硬规则（用户钉死，任何情况不放宽）

下面三条是**下限，不是目标**。做不到就不发，不要发一篇凑数的喵。

### 1. 正文至少 1000 字，推荐 1500 以上

**1000 字是硬底线，1500 是推荐值。** 用户明确说过现在的读者就喜欢长篇的，
所以能展开就别省着喵。不到 1000 就不发，1000–1500 会提示偏短。

- 字数按正文计，不含图片 Markdown、不含 `[cube_xxx]`、不含标题
- **1500–2500 最舒服**，超过 2500 考虑拆成两篇
- **自查**：写完必须跑检查脚本，不过就不要发

```bash
py scripts/check_post.py 稿子.md
```

脚本会把字数、转折词、表情密度、配图数、小标题排比一次算清楚，
不达标就退出码 1。**以脚本结果为准，不靠估。**

- 字数够但内容空（全是形容词、没有具体信息）一样不算过

### 2. 必须围绕「我选定的那一个游戏」展开

一篇帖只聊一款游戏。这是**整篇的地基**，不能中途跳车喵。

- 选定哪款就写哪款，从开头到结尾都是它
- 不允许写着写着跑去聊同类游戏、聊行业、聊别的发售
- 需要对比时，别的游戏只能当参照物出现一句，不能成为段落主角
- 标题、小标题、结尾问题，全部指向这一款

### 3. 加足随机话题，但都长在同一款游戏上

光写一条新闻撑不到 1000 字，必须往外扩喵。围绕选定的游戏，
**随机挑 2–4 个相邻话题进去**，让帖子有厚度：

| 可扩的方向 | 例子 |
|---|---|
| 玩法机制细节 | 弹反窗口、体力条设计、Boss 读指令 |
| 优化与硬件 | 驱动版本、显存占用、掉帧集中地段 |
| 前作与系列 | 上一代怎么做的、这代改了什么 |
| 社区梗与争议 | 玩家在刷什么梗、哪条差评被顶最高 |
| 内容体量与DLC | 主线多少小时、支线密度、后续计划 |
| Mod 与民间生态 | 有没有人做汉化、修复补丁、Mod 框架 |
| 玩家自己的选择 | 难度选什么、先练哪条流派 |

**“随机”的意思**：不要每次都套同一组话题，按这款游戏**实际有什么**来挑喵。
素材里提到什么就展开什么，不要为了凑字数硬加不存在的设定。

**铁律**：这些话题必须**回到同一款游戏**。跑到别家游戏就是跑题喵。

## 结构要活，别写成模板填空

**四段式（钩子 / 信息 / 判断 / 提问）是骨架，不是模具喵。**
把它当必须按顺序填的空，写出来就是公文喵。

允许而且鼓励的做法：

- **段落长短不齐**：一段三句、下一段八句，读起来才像人写的
- **插一句自己的反应**：看到某个数据时“我盯着这个数字看了半天”是可以的
- **自问自答**：抛一个问题自己接，比平铺直叙有劲
- **把判断提前**：不用非得攒到最后一段才表态
- **小标题可以不工整**：写“驱动这件事比评分还烦”这种，不必非凑成名词短语

### 情感表达：要真实的情绪，不要“客观中立”

帖子里必须有**我的立场**，而且要说出来喵。

| 要有的 | 不要的 |
|---|---|
| “这事我是真没想明白” | 全篇没有一句带情绪的判断 |
| “这个设计我不太买账” | 两头讨好、“各有优劣” |
| “看到 145G 的时候我笑了” | 假装自己没反应 |
| 具体夸/具体骂某个机制 | 空泛地说“体验不错” |

**但情绪必须长在具体事情上**喵。只写“太顶了”“麻了”而没有具体指向，
就是另一种空话喵。

另外：**情绪不是靠 `喵~` 堆出来的**。一千多字的帖子里 `喵~` 仍然控制在
3–4 处（与 `voice/profile.md` 一致），密度高了反而腻喵。情绪靠判断、靠具体的嫌弃和认可喵。

## 写帖前的强制流程（用户要求）

**第一步永远是看热搜榜**，不许凭空想选题喵。

```bash
xhh hot                  # 黑盒热议前 10 条
xhh hot -n 5             # 只看前 5
```

**第二步：看这个话题下社区高赞帖在说什么**（比第一步更重要）

```bash
xhh topic-posts "GTA6" -n 8          # 本周高互动帖
xhh topic-posts "GTA6" --time-range 30d
```

**这一步不能省。** 自己搜新闻很容易过时——实测搜「GTA6 最新消息」得到的是
"PC 版 2027 Q1 泄露"，而社区本周真正在聊的是「210GB 容量」和「预购价格」，
差了整整一个热点。

看高赞帖的**标题和摘要**，判断社区现在在聊什么角度，然后：

- **可以借鉴角度**，甚至直接顺着他们的话题写
- 但**必须用自己的话**说，不要复制原文
- 高赞帖已经说透的角度，换一个切入（他们讲容量，你可以讲下载时间和清盘）

规则：

1. `xhh hot` 看**前五条**
2. 从中挑一个，跑 `topic-posts` 看社区高赞帖在聊什么
3. **优先游戏相关**——电竞和商业新闻不适合这个号
4. 挑不出来就说明白，不要硬凑一篇
5. 写之前报一句：选的是哪条热搜、看了哪几篇高赞帖、决定写什么角度

## 方向一：游戏热点 / 测评

**找什么**：近期发售、折扣、争议、口碑反转的 PC / 主机游戏。

**素材来源**（按可靠性排）：

1. **小黑盒站内**：`xhh study` 抓推荐流，看社区已经在聊什么（别写大家已刷屏的，换个角度）
2. **Steam**：热销榜、新品榜、特别好评/差评里的高赞评论
3. **X / 微博**：搜游戏名 + "通关"、"退游"、"翻车" 看真实情绪
4. **Reddit / NGA**：找一个有争议的点

**写什么**（骨架，可拆可并，不是必须按序填满）：

```
开头钩子（1-2 句）—— 直接抛一个观察或反常识结论，别写"最近XX发售了"
中间信息（4-6 段）—— 具体数据、具体机制、具体差评在骂什么
  └─ 其中至少 2 段要是「相邻话题」：优化、前作、社区梗、Mod、体量……
我的看法（1-2 段）—— 明确站一个角度，别两头讨好
抛问题（1 句）—— 把话头递给评论区
```

写不够字数，几乎总是因为**中间信息只有新闻没有展开**喵。
把某一个机制、某一类差评写透，比多报一条消息管用喵。

**必须带具体的东西**：价格、销量、时长、某个具体机制的名字。没有具体信息就是水文喵。

**抛的问题要真的有讨论空间**：
- ✅ 「你们觉得这作的战斗节奏是快了还是拖沓？」
- ❌ 「大家怎么看？」（太空）

## 方向二：GitHub 热点项目

**找什么**：GitHub Trending 上近期涨星快的项目，尤其是普通人用得上的。

**素材来源**：

1. `https://github.com/trending`（可按语言/周期筛）
2. 项目 README 的 "What is this" 和 demo
3. star 增长曲线（三天涨 2000 星比总量 5 万星更值得写）

**写什么**（同样得过字数底线，光报一句“有个项目很火”撑不住）：

```
这是什么（1 句，说人话，别抄 README 的术语）
解决了什么痛点（2-3 段，最好举具体使用场景）
怎么装怎么用（1-2 段，具体命令、依赖、坑）
我试了/我没试（明确说，不要假装用过）
跟同类比怎么样（1 段，至少说���一个替代品）
值不值得上手（给判断，说明门槛）
抛问题（问读者有没有类似需求）
```

**硬要求**：
- 不写"赋能""生态""闭环"这类词（已在禁用词表）
- 不确定的技术细节宁可不写，不要瞎编
- star 数是引用的话要给出时间点

## 共同规范

### 长度

**所有帖都至少 1000 字，推荐 1500+**，见开头「硬规则」第 1 条喵。

读者吃长篇，所以别把 1000 当目标，那是地板喵。1000 字只够把一件事说清，
1500 字才摆得下相邻话题和自己的判断喵。

注意「硬规则」第 2、3 条（只聊选定游戏 + 相邻话题）**只适用于游戏帖**喵。
GitHub 类帖子没有“选定游戏”这回事，但字数要求一样。

### 情感：读者就是为这个点进来的

用户原话是「带有情感的」。纯信息通报没人转，带情绪的判断才会喵。

所以每篇至少要有一处**明确的个人反应**：

- 看到一个数字时的真实反应（「145G，我看完先去查了硬盘」）
- 对某个设计的具体不满（「这个弹反窗口我按三次能中一次」）
- 对官方做法的判断（「这套排查顺序是写给 PC 小白的，不是给老玩家的」）

不写「值得关注」「见仁见智」这种和稀泥的句子，那等于没表态喵。

### 格式

- 用小标题分段（article 模式支持 `<h2>`），**但标题数量别超 4 个**，多了像说明书
- 关键结论加粗，**别每段都加**——满篇加粗等于没重点
- 需要对比时用表格（会转成图片，能正常显示）
- 不列点超过 5 项，超过就分组
- **不许写“总结”章节**：结尾用自己的问题收，不要总结全文喵

### 情感与深度自检（每篇必过）

写完扪心自问：

- [ ] 有没有一句是**明确表态**的？不是“值得关注”，是“我不看好”
- [ ] 有没有至少 2 个**不是标题新闻**的相邻话题？（玩法/优化/前作/社区）
- [ ] 段落长度是不是完全一样长？（一样长 = 模板味 = 改）
- [ ] 小标题是不是四个字的整齐排比？（整齐排比 = AI 腔 = 改）
- [ ] 换个人来写，会不会写出一模一样的东西？会 → 说明没有“我”

### 表情

见 `voice/emoji.md`。一段最多 1–2 个，整篇不超过 6 个喵。连发表示无语/笑，3–5 个一组。

### 禁止句式（AI 味的重灾区）

下面这些句子一看就是机器写的，**一个都不要用**：

| 别写 | 写成 |
|---|---|
| 「问题在发售那天就摆着」 | 「早看出来了」「当初就知道要出」 |
| 「答案早就写好了」 | 「结果没出意料」 |
| 「这不是 X，这是 Y」 | 直接说 Y |
| 「时间会证明一切」 | 删掉 |
| 「真正的 X，从来不是 Y」 | 删掉 |
| 「当 X 遇见 Y」 | 删掉 |
| 「值得注意的是」「不难发现」 | 删掉 |
| 「一句话总结：」 | 删掉 |

**共同特征**：把大白话包装成文案、抽象化、爱用对仗和排比、句子里没有一个具体名词喵。

**自检方法**：这句话你会对着朋友说出口吗？说不出口就是 AI 腔喵。

具体到开头：**第一句只做两件事——说清事实，或者直接下判断**喵。
不要铺垫、不要设问、不要造悬念喵。

### 句子节奏（别写成碎片）

**一句话里逗号不超过 2 个**，句子长度要长短交错喵。

碎片化短句是 AI 腔的第二大特征，读起来像卡顿喵：

| 别写 | 写成 |
|---|---|
| 发售那阵差评就没断过，拖到现在才下，已经算慢了。 | 从发售到现在差评就没断过，这时候才下架已经算拖了。 |
| 一个 2011 年的老游戏重制，跑得比原版还差，这事本身就挺离谱。 | 一个 2011 年老游戏的重制版跑得比原版还差，这事本身挺离谱的。 |
| 幕府 2 玩家要的很简单：能跑、模组能用、画面体面点。 | 幕府 2 这代玩家要的就是能跑、模组能用、画面别倒退，没人指望它变成次世代。 |

**判断方法**：出声念一遍喵。喘不上气（太长）或者一顿一顿（太碎）都不对喵。

**小标题同样适用这条规则。** 「撤了，到现在没恢复」这种三字加逗号加六字的写法
一样是碎片，而且作为标题信息量为零。小标题要么是完整短句（「差评基本集中在四件事」），
要么干脆不要——正文第一个小标题如果只是把帖子标题复述一遍，删掉更好喵。

正常的中文长句能到 30–40 字，别怕写长喵。

### 配图（至少 3 张，动图优先）

**每篇至少 3 张图。** 纯文字帖在信息流里没人点喵。

**能动就动。** 动图比静图吸引力高一档喵，但有个硬限制：

**外链图片一律「我下载 → 我上传」**喵：

小黑盒的转存接口是他们服务器去拉外链，多数图床它访问不了（Wikimedia、giphy 都超时）喵。
但我们这台机器能访问，所以改成下载后当本地文件上传，动图也能保住动画喵。

实测可行：giphy 的 741KB / 33 帧 gif，下载后上传，返回的就是 `.gif` 能正常动喵。

所以现在**网上现成的动图可以直接用**喵，只要：

1. Markdown 里写 `![说明](https://...giphy.gif)` 或任何 http 图片地址
2. 发帖时自动下载并上传

**找动图时的注意点**：

- 优先找**和内容相关**的（讲游戏就找游戏画面，别用无关的猫猫图）
- 动图别太大，超过 3MB 上传会慢
- 无法确认是否允许转载时，注明来源或改用自己造的

**自己造**（找不到合适动图时用这个，比堆静图强）：

```bash
py scripts/make_gif.py --out .data/anim.gif --title "幕府2翻车四件事"     --line "性能倒退" --line "崩溃和新Bug" --line "模组报废" --line "画面被质疑AI"
```

生成文字轮播动图，600x360，深色底 + 红色条 + 中文字体，约 25KB喵。
Markdown 里写 `![动图](.data/anim.gif)`，发帖时自动上传喵。

**Steam 固定命名图**（不需要 hash，实测都能转存）喵：

**至少 3 张**。纯文字帖在信息流里没人点喵。

Steam 游戏的固定命名图（不需要 hash，实测都能转存）喵：

```
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/library_hero.jpg      1920x620  横幅，放开头
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/page_bg_generated_v6b.jpg 1438x809  画面感最强
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/capsule_616x353.jpg   616x353  卡片式
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/library_600x900.jpg   600x900  竖版封面
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/header.jpg            460x215  最小
https://cdn.akamai.steamstatic.com/steam/apps/<appid>/logo.png              640x360
```

**图片来源的硬限制**：小黑盒的转存服务器只认它能访问的站喵。
实测 Steam CDN 可以，Wikimedia 等会超时喵。转存失败会直接报错，不会静默吞掉喵。

### 标题

- 不用「震惊」「必看」这类标题党
- 带具体信息：「XX 降价到 99，值得现在入吗」比「一个好消息」好
- 不超过 30 字

### 绝对禁区

| 禁止 | 原因 |
|---|---|
| **政治、时政、政策** | 不谈。一个字都不碰 |
| 医疗、法律、投资建议 | 无法负责 |
| 评价真人主播/博主 | 容易引战 |
| 判断「某个价格是否合理」 | 掺进利益判断就变味 |
| 编造第一人称经历 | 规格 C4，比语气问题严重 |
| 搬运他人内容不注明 | 至少说一句"看到有人说" |

### 发布前自检

- [ ] **正文字数 ≥ 1000**（硬规则，推荐 1500+）
- [ ] **全篇只聊我选定的那一款游戏**
- [ ] **扩了 2–4 个相邻话题，且都长在这款游戏上**
- [ ] 至少有一段是明确表态，不是中立叙述
- [ ] 段落长度不整齐，小标题不排比
- [ ] 分区挂了 PC区 + 游戏专属区（两个）
- [ ] 标题不含标题党词汇
- [ ] 有具体数据/机制，不是纯观点
- [ ] 结尾有可讨论的问题
- [ ] 表情数量 ≤6
- [ ] 没碰禁区和编造经历
- [ ] 读一遍：像人说的话吗（转折词堆砌就是 AI 腔）
